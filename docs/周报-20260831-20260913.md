**按老师意见补上的细节**

- **MedQA 怎么得分**：统一解析 `最终答案: X`，对错计 0/1，无效作答记 0 并进分母；解释质量不入分。
- **Recall / Precision 怎么估**：评价单元对齐知识库 ID（如 `nccn:BCEL-5`）；主指标用最终回答的引用集合，检索列表只作诊断；空引用 Precision=0；负向题改报正确拒绝率与幻觉引用率。
- **病历怎么抽、抽多少**：分层脱敏约 20 例 × 10 题 = 200 题；医生先标 50 题种子（20 题双标）；自主评分须过相关与安全门槛后，才可打剩余 150 题。

**产出**：评估思路 PPT（后收成一张架构图 + 测评箭头）；成型文档见 `docs/评估方案.md`（含 A–E 记录表）。文档在周期结束次日（9.14）按汇报意见落盘。

### 1.2 交互设计：分子证据并入 QA，而不是再开一页

现状：分子证据是独立页；顶栏按钮是**跳转**，不是能力开关。目标：用户在问答框提问，勾选分子证据后，**同一对话里给出综合答案**。

**本周结论（设计，尚未改线上交互）**

- 真正的难点不在「把链接改成开关」，而在两条链路范式不同。
  - **QA**：LLM 流式生成，证据可被模型改写，走 SSE。
  - **分子证据**：正则解析 → ClinVar / CIViC / MyVariant → 模板成文，带安全门控，**运行时不调大模型**。
- 同事口头说的「分子证据用了大模型 / 是一个 agent」，和仓库不一致：类名带 Agent，实际是确定性检索 + 规则成文。按组内口径，**没有接入 LLM 的不叫智能体**。整套产品是「一个问答智能体 + 一条独立工具链」，不是多智能体系统。
- 「综合答案」有两条路，需要先拍板再写代码：
  1. **拼接**：指南回答与分子报告分区并列，安全、可溯源，但不够「像一次问诊」。
  2. **LLM 融合**：让问答模型改写分子结果，体验更好，但可能改掉门控后的措辞，有安全风险。
- 建议落地顺序：先做开关 + 分区拼接，融合放在门控句不可改写的约束之后。
